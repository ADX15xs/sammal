# SMOKE.md — 三终端实机冒烟指引（渐进落盘）

> 对应 DEBT.md `internal/tui/scroll.go` 条目的偿还项：渐进落盘的正确性依赖终端的
> 真实行为（宽度折算、滚动插入、光标钳制），单元测试证明不了实机。本文档是傻瓜式
> 步骤，照着做即可，不需要任何测试知识。
>
> - **适用版本**：渐进落盘首次落地的提交（6e04ae0）及之后
> - **总耗时**：单终端约 10 分钟；有几个终端测几个，没有的标「未测」即可

---

## 0. 先搞懂：什么叫「通过」

sammal 的回答会一边生成一边「打印」到你终端上方的滚动区（就是用鼠标滚轮能滚上去
看的那块历史区域）。这次改动管的就是这个打印过程不出错。

**正常的样子**：回答像普通聊天软件一样，一行接一行往上长；底部的输入框和状态栏
始终钉在屏幕最下方；滚上去看历史，文字连续完整。

**错位的样子**（出现任意一条 = 失败）：

1. 回答的**文字窜到了屏幕顶部**——顶上突然出现几行不该在那里的回答内容；
2. 回答的**中间出现大段空白**——滚到某处发现空了几十行，文字跳过去了；
3. **输入框/状态栏跑位**——跑到屏幕中间、消失、或者和文字重叠；
4. 打印结束后**继续输入，新回显的位置不对**（和上一条回答重叠或隔着大段空行）。

## 1. 准备（每个终端环境做一次）

### 1.1 构建

在项目目录执行：

```
go build -o sammal ./cmd/sammal
```

Windows 下得到 `sammal.exe`，Linux/macOS 下得到 `sammal`。下面用 `./sammal` 指代
（Windows 请自行读作 `.\sammal.exe`）。

### 1.2 确认能跑通

在**待测终端**里启动 `./sammal`，随便发一句话能得到回答。你日常的 config.toml
不用动。

### 1.3 往剪贴板放一条「超宽单行」（T3 要用）

Windows PowerShell 里执行（二选一，建议两个都放，用的时候重新执行即可）：

```powershell
'中' * 1500 | Set-Clipboard     # 1500 个汉字 = 3000 列显示宽（CJK 用例）
'a'  * 3000 | Set-Clipboard     # 3000 个字母（ASCII 用例）
```

Linux/macOS 用：`printf '中%.0s' {1..1500} | xclip -selection clipboard`（没装
xclip 就跳过 CJK 版，只做 ASCII 版：`printf 'a%.0s' {1..3000} | xclip -selection clipboard`）。

### 1.4 三个终端环境怎么进

| 终端 | 怎么进 | 说明 |
|---|---|---|
| **Windows Terminal** | 开始菜单打开 Windows Terminal，`cd` 到项目目录，跑 `.\sammal.exe` | **必测**（你的主力环境） |
| **WSL + tmux** | 先 `wsl` 进 WSL，`sudo apt install tmux`（装过跳过），然后 `tmux`，在 tmux 里 `cd /mnt/d/github-clone/sammal && go build -o sammal ./cmd/sammal && ./sammal` | 有 WSL 就测；tmux 里 go/config 都要在 WSL 侧备好，嫌麻烦可跳过 |
| **macOS iTerm2** | 需要一台 Mac：装 Go，clone 仓库，构建后在 iTerm2 里跑 | 没有 Mac 就跳过 |

⚠️ **终端窗口别太矮**：高度至少 20 行（tmux 别用小分屏窗格）。特别矮的窗口不在
保证范围（DEBT 已记账）。

## 2. 测试用例（每个终端从 T1 到 T5 各跑一遍）

> 每个用例开始前建议 `/new` 开个干净会话。T1-T4 全程只盯着这一个终端；
> T5 需要你再开一个终端窗口（不用跑 sammal）。

### T1 长回答渐进落盘（核心用例）

**步骤**：

1. 发送这条消息（直接复制粘贴）：

   ```text
   请从 1 编号到 300，每行一条。格式严格为「N. 一句话」，不要任何解释，直接开始。
   ```

2. 盯着屏幕看整个生成过程（一两分钟）；
3. 生成结束后，用鼠标滚轮从底部一路滚到这条回答的开头，再滚回来。

**你会看到**：回答逐行长出来；生成中底部有一个「流式尾部窗口」只显示最后几行，
前面的行已经打印进滚动区了。

✅ **通过**：全程无第 0 节列出的任何错位现象；从头到尾 300 行连续完整、顺序正确。

❌ **失败**：出现错位。**记下是哪条特征（1-4）+ 大概在第几行附近**。

### T2 流式期间滚动 / 复制（这次改动的附带收益）

**步骤**：趁 T1 还在生成时（进行到一半最好）：

1. 鼠标滚轮往上滚几屏（tmux 里按 `Ctrl+B` 然后按 `[`，用方向键滚，按 `q` 退出）；
2. 用鼠标划选一小段已经打印出来的文字，复制（Windows Terminal：`Ctrl+Shift+C`；
   iTerm2：`Cmd+C`；tmux 不会用就跳过复制，只验滚动）；
3. 滚回底部，确认生成还在继续、没有中断。

✅ **通过**：滚动流畅、复制到的文字连续可读；回到底部后生成照常进行。

❌ **失败**：滚动时画面破碎、复制内容缺失或乱序、回到底部后回答不再增长。

### T3 超宽单行粘贴回显

**步骤**：

1. 重新执行 1.3 的 PowerShell 命令放「1500 个汉字」进剪贴板；
2. 在 sammal 输入框按 `Ctrl+V` 粘贴，然后按 Enter 发送；
3. 重新放「3000 个字母」，重复一遍。

✅ **通过**：回显原样打印（一行很长的文字折成约 40 行），无错位；输入框清空正常。

❌ **失败**：回显打印时发生错位，或回显内容明显缺字/多字。

### T4 Esc 中止

**步骤**：重发 T1 的长问题，等回答出来 10 行以上后按 `Esc`。

**你会看到**：回答停止，出现一行暗色的「（以上内容被中断）」和一行「（已中止）」。

✅ **通过**：标记出现、位置正确（紧跟在已流出的内容之后）；之后正常输入发送无错位。

❌ **失败**：中止后文字错位、标记丢失、或无法继续对话。

### T5 流中断重连 + 作废标记（需要动手「弄坏」网络）

原理：生成中途把模型服务杀掉，sammal 会自动重连（最多 5 次，累计约 30 秒窗口），
重连成功后会在滚动区打一行暗色作废标记。**这是本次改动里唯一会「作废已显示内容」
的路径，必须实机看过。**

**本地 Ollama 用户（A 法）**：

1. 发送 T1 的长问题，等前 10 行以上打印出来；
2. **另开一个终端窗口**（不用进 sammal），执行：

   ```
   taskkill /f /im ollama.exe
   ```

   （Linux/macOS：`pkill ollama`）
3. 回到 sammal：应出现暗色状态行「| 流中断：…；Ns 后重连（1/5）」，随后（2/5）、（3/5）……
4. **马上重启 Ollama**（开始菜单点 Ollama 图标，或在新终端窗口跑 `ollama serve`）；
5. 等 sammal 自动重连成功。

**远程端点用户（B 法）**：发送长问题，等 10 行以上后**关掉 Wi-Fi 约 5 秒再打开**，
其余观察点相同。

**你会看到**：重连成功后出现一行暗色「（流中断重连：上方未定稿内容已作废）」，
然后一个**全新的回答**从头开始流出并完整定稿。

✅ **通过**：作废标记恰好一行、位置正确；新回答完整；全程无错位。

❌ **失败**：标记缺失/重复/位置错乱，或重连后文字错位。

💡 两个常见情况不算失败：

- 出现「超过单次等待上限，停止自动重试」——你重启太慢（或模型加载超过 30 秒），
  5 次重试预算用完了。这是设计好的安全失败路径，**再跑一次、重启快一点**即可；
- 模型越大加载越慢，时间紧可临时在 config.toml 换个小模型做这个用例。

## 3. 观察项（不判失败，看到就记账）

这两条是 DEBT 已登记的**已知残余边界**，实机错位了不阻塞冒烟通过，但正是它们的
修复触发条件，必须记下来：

- **观察项 ①（tab 宽度）**：发「写一段 Go 代码，用 tab 缩进，放在代码块里原样输出」。
  若代码块区域出现错位 → DEBT 残余项 ① 实机复现；
- **观察项 ②（空行 artifact）**：跑 T1 和 T5 时留意回答里是否**多出成排的空行**。
  出现 → DEBT 残余项 ③（打印与 ticker 交错）实机复现。
