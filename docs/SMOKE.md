## 0. 先搞懂：什么叫「通过」

sammal 的回答会一边生成一边「打印」到你终端上方的滚动区（就是用鼠标滚轮能滚上去看的那块历史区域）。这次改动管的就是这个打印过程不出错。

**正常的样子**：回答像普通聊天软件一样，一行接一行往上长；底部的输入框和状态栏始终钉在屏幕最下方；滚上去看历史，文字连续完整。

**错位的样子**（出现任意一条 = 失败）：

1. 回答的**文字窜到了屏幕顶部**——顶上突然出现几行不该在那里的回答内容；
2. 回答的**中间出现大段空白**——滚到某处发现空了几十行，文字跳过去了；
3. **输入框/状态栏跑位**——跑到屏幕中间、消失、或者和文字重叠；
4. 打印结束后**继续输入，新回显的位置不对**（和上一条回答重叠或隔着大段空行）。

> **校准「大段空白」**：连续 **≥5 行**空行才算失败；1-2 行的段落间隔是正常的。「窜到顶部」指回答内容出现在屏幕**最顶上一行**（正常顶部要么是更早的历史、要么是空的，绝不该是当前正在生成的回答）。拿不准时：**把窗口截图，和上面 4 条逐条比对**。
>
> **判据优先级**：本节是通用判据。T11 对「思考行与其下答案之间」单列了更严的 **0 空行**要求，两者冲突时以 T11 为准——那里的一条空行就是被修的缺陷本身，不是段落间隔。

## 1. 准备（每个终端环境做一次）

### 1.1 构建

在项目目录执行（Go 已装、config.toml 已就位，直接 build）：

```
go build ./cmd/sammal
```

不带 `-o` 时 Go 按平台自动命名：Windows 下得到 `sammal.exe`，Linux/macOS 下得到 `sammal`。（不要写 `-o sammal`：`-o` 的名字会原样落盘，Windows 下得到无扩展名的 `sammal`，无法直接运行。）下面用 `./sammal` 指代（Windows 请自行读作 `.\sammal.exe`）。

### 1.2 确认能跑通

在**待测终端**里启动 `./sammal`，随便发一句话能得到回答。你日常的 config.toml 不用动。

> 启动报「创建会话失败：mkdir … Access is denied」时不是 sammal 的锅：根因是**项目目录被第三方安全软件打了 Low 强制完整性标签**（`icacls` 可见 `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)`，本机 2026-11-01 晚间出现，与火绒安装时间吻合；卸载安全软件标签仍残留）。目录内新构建 exe 继承 Low 标签 → 进程以低完整性运行 → 「不向上写」策略禁止写一切 Medium 对象（AppData、D:\Temp 全中枪）；cp 出去丢标签能跑、目录内改名保留标签被拦、提权豁免——皆由此。修复（已执行）：`icacls "D:\github-clone\sammal" /setintegritylevel M`，新构建即恢复正常。若复发（安全软件重打标签）同法重置。

### 1.3 往剪贴板放一条「超宽单行」（T3 要用）

Windows PowerShell 里执行（二选一，建议两个都放，用的时候重新执行即可）：

```powershell
'中' * 1500 | Set-Clipboard     # 1500 个汉字 = 3000 列显示宽（CJK 用例）
'a'  * 3000 | Set-Clipboard     # 3000 个字母（ASCII 用例）
```

Linux/macOS 用：`printf '中%.0s' {1..1500} | xclip -selection clipboard`（没装 xclip 就跳过 CJK 版，只做 ASCII 版：`printf 'a%.0s' {1..3000} | xclip -selection clipboard`）。

### 1.4 三个终端环境怎么进

| 终端 | 怎么进 | 说明 |
| --- | --- | --- |
| **Windows Terminal** | 开始菜单打开 Windows Terminal，`cd` 到项目目录，跑 `.\sammal.exe` | **必测**（你的主力环境） |
| **WSL + tmux** | 先`wsl` 进 WSL，`sudo apt install tmux`（装过跳过），然后 `tmux`，在 tmux 里 `cd /mnt/d/github-clone/sammal && go build ./cmd/sammal && ./sammal` | 有 WSL 就测；tmux 里 go/config 都要在 WSL 侧备好，嫌麻烦可跳过 |
| **macOS iTerm2** | 需要一台 Mac：装 Go，clone 仓库，构建后在 iTerm2 里跑 | 没有 Mac 就跳过 |

⚠️ **终端窗口别太矮**：高度至少 20 行（tmux 别用小分屏窗格）。特别矮的窗口不在保证范围（DEBT 已记账）。

## 2. 测试用例（基线 T1-T6 必跑，增强 T7-T11 建议同轮跑）

> 每个用例开始前建议 `/new` 开个干净会话。T1-T4、T6-T11 全程只盯着这一个终端；T5 需要你再开一个终端窗口（不用跑 sammal）。T7 与 T9 都复用 T1 的长回答，可在同一次生成里先做 T7 再发 T9 的插话，不必各自重发一遍长问题。

### T1 长回答渐进落盘（核心用例）

**步骤**：

1. 发送这条消息（直接复制粘贴）：

   ```text
   请从 1 编号到 300，每行一条。格式严格为「N. 一句话」，不要任何解释，直接开始。
   ```

2. 盯着屏幕看整个生成过程（一两分钟）；
3. 生成结束后，用鼠标滚轮从底部一路滚到这条回答的开头，再滚回来。

**你会看到**：回答逐行长出来；生成中底部有一个「流式尾部窗口」只显示最后几行，前面的行已经打印进滚动区了。

✅ **通过**：全程无第 0 节错位；**滚到顶能看到「1.」开头、滚到底能看到「300.」结尾，中间任意位置没有超过 5 行的连续空白**，顺序正确。

❌ **失败**：出现错位。**记下是哪条特征（1-4）+ 大概在第几行附近**。

💡 模型没给足 300 行（偷懒/收尾早）：≥50 行仍算有效（渐进落盘的触发线很低，50 行早已越线）；不足 50 行重发一次，仍不足则本用例标「非结果」，不算失败。

### T2 流式期间滚动 / 复制（这次改动的附带收益）

**步骤**：趁 T1 还在生成时（进行到一半最好）：

1. 鼠标滚轮往上滚几屏（tmux 里按 `Ctrl+B` 然后按 `[`，用方向键滚，按 `q` 退出）；
2. 用鼠标划选一小段已经打印出来的文字，复制（Windows Terminal：`Ctrl+Shift+C`；iTerm2：`Cmd+C`；tmux 不会用就跳过复制，只验滚动）；
3. 滚回底部，确认生成还在继续、没有中断。

✅ **通过**：滚动流畅、复制到的文字连续可读；回到底部后生成照常进行。

❌ **失败**：滚动时画面破碎、复制内容缺失或乱序、回到底部后回答不再增长。

### T3 超宽单行粘贴回显

**步骤**：

1. 重新执行 1.3 的 PowerShell 命令放「1500 个汉字」进剪贴板；
2. 在 sammal 输入框按 `Ctrl+V` 粘贴，**输入框会显示折叠标记 `[paste #1 +1 lines]`**，然后按 Enter 发送；
3. 重新放「3000 个字母」，重复一遍。

**你会看到**：按 Enter 后 sammal 会把你这条消息以「> 」开头**完整原文**打进滚动区（回显是全文，不是折叠标记），超宽一行由终端折成一大段多行。本用例说的「回显」就是这个，是客户端行为、**和模型无关**：随后模型回复了什么、回得好不好都不影响判定，嫌刷屏可在回复开始后按 Esc 中止。粘贴后输入框显示折叠标记也属正常（大段粘贴 ≥10 行或 ≥1000 字符会折叠为原子标记，完整文本随 Enter 提交）。

✅ **通过**：回显连续完整、无缺字/多字（行数随窗口宽度变，不用数），无第 0 节错位；输入框清空正常。

❌ **失败**：回显打印时发生错位，或回显内容明显缺字/多字。

💡 肉眼数 3000 个字符不可靠，用剪贴板客观校验：把整段回显划选复制后，粘贴进 PowerShell 执行——

```powershell
((Get-Clipboard -Raw) -replace "`r?`n","").Length    # 应等于 1500 或 3000
```

终端折行会引入换行符，去掉再数才准。差 1-2 个字符多是划选时多带/少带了首尾，重划一次再量；差几十以上才算真缺字。

**校准：「自动折行」与「自动分段」是两回事**（2026-11-02 术语修正）：

- **折行（soft wrap）**：应用打一行逻辑行，终端在窗口宽度处视觉折行；复制时软折行拼回一行。永远正常，不判失败。
- **分段（hard split）**：单行折行数超过落盘预算（`printMargin` = 窗口行数 − 14 − 输入框额外行，下限 1）时，应用在落盘前把巨行切成若干段（scroll.go `splitForPrint` 巨行硬拆），每段 `margin×w−1` 显示列，**段间是真实换行**，复制出来就是多行。设计行为：单次 Println 折行数超视口余量正是渐进落盘要治的「窜顶/大段空白」病根，分段不可避免（除非回显不打全文）。触发完全由 行宽×窗口宽×窗口行数 决定，**不是偶现**。回显字数完整即判通过。

分段验证法：登记**该用例运行时刻**的窗口列×行（登记时刻的窗口可能已变过），按段宽公式 `margin×w−1` 预测分割点与复制结果比对。

**本用例同时覆盖 DEBT 残余项②（巨行硬拆不切 ANSI 序列）**：回显首行带着色转义序列，超宽硬拆若切在序列中间会出现乱码色块。通过即②实机闭环——登记时在 T3 行备注「覆盖②」。

### T4 Esc 中止

**步骤**：重发 T1 的长问题，等回答出来 10 行以上后按 `Esc`。

**你会看到**：回答停止，紧跟已流出内容之后出现一行暗色的「（以上内容被中断）」。若中止时还没有任何内容流出，显示的是「（生成中断，内容未定稿）」——本用例等了 10 行才按 Esc，正常不会遇到。

✅ **通过**：标记出现、位置正确（紧跟在已流出的内容之后）；之后正常输入发送无错位。

❌ **失败**：中止后文字错位、标记丢失、或无法继续对话。

### T5 流中断重连 + 作废标记（需要动手「弄坏」网络）

原理：生成中途把模型服务杀掉，sammal 会自动重连（最多 5 次，累计约 30 秒窗口），重连成功后会在滚动区打一行暗色作废标记。**这是本次改动里唯一会「作废已显示内容」的路径，必须实机看过。**

**先用哪个法？**：本地跑 Ollama 的走 A 法；连远程端点（豆包 / DeepSeek 兼容等）的走 B 法——B 法不用碰命令行，更简单。

**本地 Ollama 用户（A 法）**：

1. 发送 T1 的长问题，等前 10 行以上打印出来；
2. **另开一个终端窗口**（开始菜单再点一次 Windows Terminal 即可，不用进 sammal），执行：

   ```
   taskkill /f /im ollama.exe
   ```

   （Linux/macOS：`pkill ollama`）

3. 回到 sammal：应出现暗色状态行「| 流中断：…；Ns 后重连（1/5）」，随后（2/5）、（3/5）……
4. **马上重启 Ollama**（开始菜单点 Ollama 图标，或在新终端窗口跑 `ollama serve`）；
5. 等 sammal 自动重连成功。

**远程端点用户（B 法）**：发送长问题，等 10 行以上后**关掉 Wi-Fi 约 5 秒再打开**，其余观察点相同。**台式机/无 Wi-Fi**：拔网线 5 秒插回；或用管理员 PowerShell 断网——`Get-NetAdapter` 查在用网卡名，`Disable-NetAdapter -Name "以太网" -Confirm:$false`，约 5 秒后 `Enable-NetAdapter -Name "以太网"`。

**你会看到**：重连成功后出现一行暗色「（流中断重连：上方未定稿内容已作废）」，然后一个**全新的回答**从头开始流出并完整定稿。

✅ **通过**：作废标记恰好一行、位置正确；新回答完整；全程无错位。

❌ **失败**：标记缺失/重复/位置错乱，或重连后文字错位。

💡 两个常见情况不算失败：

- 出现「超过单次等待上限，停止自动重试」——你重启太慢（或模型加载超过 30 秒），5 次重试预算用完了。这是设计好的安全失败路径，**再跑一次、重启快一点**即可；
- 模型越大加载越慢，时间紧可临时在 config.toml 换个小模型做这个用例。

### T6 tab 代码块回归（制表位展开修复的实机确认）

**步骤**：发送这条消息：

```text
   写一段 Go 代码，用 tab 缩进、放在代码块里原样输出，不要任何解释。
```

**你会看到**：回复里出现一段用 tab 缩进的 Go 代码。这曾是 DEBT 残余项①（`\t` 被算成 0 宽 → 折行数低估 → 错位），现已修复：落盘前按 8 列制表位把 `\t` 展开为空格。

✅ **通过**：代码块区域无错位。

❌ **失败**：代码块区域错位 → 修复回归，按失败登记。

💡 若模型输出的代码是用**空格**缩进而非 tab：重发一次提示词；仍用空格则该终端的 T6 标「非结果」（模型没按 tab 输出，本用例无法验证），不算失败。

### T7 流式期间扰动帧高（resize + 多行输入，增强用例）

原理：落盘预算与折行宽度按**当前**窗口尺寸实时计算，改动立即生效；已落盘的行按旧宽度冻在滚动区里，新批次按新宽度算——这是把「窜到顶部/大段空白」逼出来的最强操作，单测覆盖不了真实终端的重排行为。

**步骤**：

1. 重发 T1 的长问题；
2. 生成进行中做三件事（顺序随意）：
   - 鼠标拖窗口右边框，把宽度压窄一半，停两秒，再拖回（做两次）；
   - 把窗口**高度**压到 16 行左右并保持到本回答结束——落盘预算在矮窗下退化为逐行落盘，是最保守也最缺实机验证的路径；窗口拖不到这么矮就跳过这一步；
   - 在输入框用 `Ctrl+J`（或 `Alt+Enter`）打出 3-4 行字（**不要**按 Enter 发出），再逐个删掉；
3. 等回答定稿，滚轮从这条回答的开头一路检查到结尾。

✅ **通过**：扰动过程中与定稿后均无第 0 节错位；滚动区文字顺序连续。

❌ **失败**：出现错位。**记下是哪个扰动动作（改宽/打字）+ 大概在第几行附近**。

### T8 /resume 长会话转录回放（增强用例）

原理：`/resume` 会把整条历史会话的转录**一次性**打进滚动区（不是流式逐批），是另一种形态的巨批落盘，T1 的流式路径覆盖不到它。

**步骤**：

1. 确保你有一条含长回答的历史会话（跑过 T1 的那个就是）；
2. 发 `/new` 开个干净会话，然后发 `/resume`，按序号选回那条长会话；
3. 滚轮从转录开头一路检查到结尾。

✅ **通过**：转录完整连续（能看到当时的「1.」到「300.」），无第 0 节错位；之后正常发问、回答无错位。

❌ **失败**：回放时错位或转录明显缺段。

### T9 生成中插话（Steering 回显落盘，增强用例）

原理：生成进行中再发一条消息，你的回显会**立刻**落进滚动区，与正在进行的流式落盘交错——这是 DEBT 残余项③（打印与心跳交错）触发面最大的用户操作，相当于观察项的主动诱发版。

**步骤**：

1. 重发 T1 的长问题；
2. 趁生成进行到一半，在输入框打一句短话（如「先停一下，第 50 行附近是什么内容？」）按 Enter 发出；
3. 紧接着再发两条同结构的短话（「第 100 行」「第 200 行」附近），间隔几秒即可；
4. 观察回显与提示的落点、后续生成；回答定稿后滚轮全程检查一遍，再 `/resume` 复核；
5. 再发一条短话（如「继续」），随后按 `↑` 召回同一句、立刻再按 Enter——模拟「催一下」的自然重复。

✅ **通过**：

- 每条插话的回显完整出现在滚动区，且**下一行紧跟灰字 `（消息已发出，请等待模型响应）`**；
- 提示**不堆积在长输出末尾**（旧实现在 300 行写完后才连出三条「已吸收插话」，本用例即防此回归）；
- **模型在本 turn 内看见插话，且对三条逐条回应**（续答或后续输出体现三条要求）；
- `/resume` 回放里三条插话是**一条合并消息**（带「生成中插话 3 条，按先后顺序」抬头 + 1./2./3. 序号），不是三条独立消息；
- 第 5 步的重复插话**两次都发出**：屏幕出现两条回显、各自带提示，`/resume` 里是 1./2. 两条（内容相同）——投递层不再按时间窗猜重复（2026-11-04 删除），按了几次就发几条——**模型把这两条相同内容按一次做掉不判失败**（它有权这么判），只要转录里两条都在；
- 回答继续生成至定稿；全程无第 0 节错位、无成片多余空行。

❌ **失败**：回显或回答错位、回显丢失、**模型对插话零响应**、**模型只回应最后一条**（说明合并语义仍不足 → 转 T15 steer 决策；该用例尚未立项，见文末「已知未覆盖」）、`/resume` 无插话、提示出现在输出末尾。

### T10 IME 中文输入序列（发布前常设 + 行中插入回归）

### T11 思考行下沉（思考结束不留空洞）

原理：思考实时只显示一行（尾部跟随），结束时把**该行**下沉进滚动区再撤帧——滚动区 +1 / 帧 −1 抵消，视觉上原地保留。旧实现直接撤行，帧高 3→2 而滚动区无新增，用户回显与答案首行之间留下一条空行（`1793561168405.png` 即此症状）。落盘增量恒为 1 行，与思考长度无关；`/resume` 仍不含思考（结论视图的既定差异）。

**步骤**：

1. 用会产出 reasoning 的模型（DeepSeek reasoning / qwen3 thinking 等）发一条会触发思考的问题，长问题更易观察；
2. 盯住思考行（`- 思考中 12s | …`）消失的那一刻；
3. 检查用户回显与答案首行之间，再滚轮看完整回答；
4. 发 `/resume` 选回本条会话：回放里**不应**出现思考行（结论视图的既定差异）；
5. （可选，与 T5 合并做）思考进行中按 T5 的方式断流重连：作废的思考**不下沉**，滚动区只留重连后的新思考行。

✅ **通过**：思考原位置留下**一行暗色 `- 思考 Ns | …`**；其下紧跟答案，**中间没有空行**；思考行不重复出现两次以上；回答中无成片多余空行；`/resume` 回放不含思考行；模型在只调工具的 step 只吐换行、或给正文加前后换行 padding 时，思考行与紧随内容（工具行/答案首行）之间同样 **0 空行**。

❌ **失败**：仍有空行空洞、思考行重复出现（非瞬时）、答案被思考行覆盖、断流后作废的思考被下沉进滚动区。

> 注：队列排空期间 `frameHold` 会冻帧，思考行可能短暂重复一帧（毫秒级），属既定行为，不判失败。
